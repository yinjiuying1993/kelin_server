# 聊天双 Agent 完善方案

对照四份材料：

- 体验规则：`0_kelin/v1/聊天/kelin_v1_chat_rules.md`
- Agent 细则：`0_kelin/v1/聊天/kelin_v1_chat_agents_spec.md`
- 算法施工：`0_kelin/v1/聊天/聊天算法模块施工说明书.md`
- 业务施工：`0_kelin/v1/聊天/聊天业务模块施工说明书.md`
- 现行代码：`app/services/chat.py`、`app/domain/chat/`、`app/services/memory/extract_worker.py`

只排「算法或业务施工说明书已经写了、请求路径没接上」的改动。Agent 细则有、施工说明书没有或互相冲突的，放在文末，不进实现批次。

聊天仍只写消息、窗口轮次和 `dialogue.completed`。长期记忆仍由记忆模块准入后落库。不改五维、饥饿、精力、去向、情绪公式。不改 iOS。不把口癖样本加回提示词。

一次只做下面的一个批次。每批都要有纯函数测试；碰库或百炼入参的批次再补一条 db 测试。不顺手改相邻行为。

## 现在实际在跑的路径

在家的普通一轮：

1. 结算去向和情绪。
2. 去向不是 `home` 时直接 `409 SPIRIT_NOT_HOME`，不调用模型，不写消息。
3. 在家且命中安全词时，用固定安全句落库，`counts_ordinary=false`。
4. 其余在家轮次把用户原文、最多 20 条记忆、一段情绪预算文本交给百炼，模型正文直接落库。

`plan_turn`、`assemble_instruction`、`validate_reply`、`apply_overlay` 都在 `app/domain/chat/`，单测能过。请求路径不用它们决定生成。`render_emotion_context` 会用真实档位再调一次 `plan_turn`，但只把句数写进提示，不验收模型正文。

抽取：满 3 个普通轮封窗，一个 outbox 任务。Worker 调 `extract`，再用 `accepted_memories` 按置信度 ≥ 0.75、摘要截到 500 字、最多 2 条收下。`admit()` 没有被 worker 调用。`chat_overlays` 表在建精灵时插入空 payload，聊天不读不写。

## 不改的部分

这些已经按现行产品或施工说明书落地，不要在接 Agent 时改回去：

- 走失、求知、串门不产生聊天。接口是 `409`，错误码 `SPIRIT_NOT_HOME`。算法施工和 Agent 细则仍写「只找回 / 出门短句」。以已经落地的拒绝为准，不恢复「先把我叫回去。给我口粮。」和「我出去了。……」。
- 走失时的安全话也不再生成。细则写安全高于走失；现行产品是人在外面就不聊。本方案不把走失安全加回来。
- 在家的安全固定句仍走 `_gate_reply`，不计普通抽取轮。
- 同一 `client_message_id` 重放返回原消息，不重复扣配额。
- 模型失败不落精灵回复，不形成完整轮次。
- TTS 只朗读已落库正文，每日最多 20 条；失败或超限仍返回文字。
- 口癖样本不进提示、不从抽取结果落库。算法施工写明一期不用口头禅。
- 抽取失败保留对话，同一窗口可重试；已 `extracted` 的窗口重放不追加记忆。
- 聊天服务不 `insert_memory`，不写性格 delta。

领域函数里的 `recall_only` / `away_note` 降级句可以留着给算法单测。服务层在进生成之前已经拒绝，活路径到不了这两句。

## 批次 1：在家计划用结算结果 — 已完成

`plan_settled_turn` 用本轮结算的去向、阶段、饥饿档、精力档、主标签、五维、时辰、用户原文组一份计划。`_settled_chat_plan` 只组一次；`render_emotion_context` 和 `_gate_reply` 共用它。`satisfied` / `irritated` 按 `content` / `irritable` 取预算。非在家仍先 `SPIRIT_NOT_HOME`。本批不校验模型正文、不写 Overlay。

## 批次 2：不合规正文不落库 — 已完成

`ChatOutput.intent` 改为 `safety` / `recall_only` / `away_note` / `knowledge` / `tired` / `hungry` / `companion`，缺省是空。百炼返回后先 `validate_reply`。结构、意图、句数、提问、禁词、首句职责、轻刺、系统口吻失败时不保存模型正文，改存该模式降级短句，引用清空。依据是否装懂仍放过，留给批次 4。安全模式仍不调用百炼。模型不可用仍不写消息。

## 批次 3：结构失败只重试一次 — 已完成

校验失败或聊天 JSON 无法解析（`CHAT_OUTPUT_INVALID`）时再调一次。第二次提示带上失败码、模式、句数和提问上限。第二次仍失败才落降级短句。超时、取消和其它供应商错误不重试。两次调用都在落库事务之外。

## 批次 4：指令包是模型唯一上下文 — 已完成

在家非安全轮次只发送指令包：模式和预算、去向、阶段、饱食档、精力档、主标签、五维档、称呼槽、白名单记忆、最近 6 条消息、时辰、星期、依据。不再另附情绪预算散文，也不把记忆列表再贴一次。幼灵不写熟悉摘要。知识且白名单没有知识记忆时依据为无；正文含「你教过」则降级。检索调用保持原样。

## 批次 5：Overlay 下一轮生效 — 已完成

每轮在家聊天用用户原文更新 `chat_overlays.payload`，并和消息同一事务把 `overlay_version` 加一。封存主题不能被覆盖，除非原文含「可以重新记住」。本轮校验使用新 Overlay，禁止称呼当轮就生效。勿记主题不再进入可引用记忆。聊天不把 Overlay 写成记忆页。

## 批次 6：按阶段选记忆，不按 20 条灌入 — 已完成

召回仓库仍按 `PROMPT_MEMORY_LIMIT = 20` 读取活跃记忆。聊天组包前再按下面的规则挑选，不再把这 20 条都灌进指令包。熟悉摘要没有可追溯正文，服务端不编造。

在家组指令包前：

- 只读 `active`。
- 必带称呼、禁止称呼、雷区，各最多 1，且不被普通条挤掉。这些不算「点到一件往事」。
- 普通条必须能对上本轮用户原文或最近两轮里的主题词。对不上的丢掉，即使显著度更高。
- 总数不超过该阶段上限，含必带。
- 熟悉摘要：幼灵 0，成形最多 1，觉醒最多 2。没有可追溯的 active 证据就不造摘要。
- 模型引用的 id 必须属于这包白名单。多出来的引用去掉；正文仍在讲包外事实则整单失败，走降级。

不在本批改记忆页的写入规则。测试：幼灵有 10 条活跃记忆时包内最多 3 条；与本轮无关的高显著条不出现。

## 批次 7：主标签补约定和传授 — 已完成

`classify_user_text` 已补上约定和传授。任意「辞职」不再抢在疑问词前面，「辞职流程是什么」按知识问。

命中即停，保持施工顺序：

```text
安全 > 纠正 > 勿记 > 改口 > 记住 > 约定 > 知识问 > 传授 > 倾诉 > 玩笑 > 闲聊
```

封闭词表，宁漏勿造：

| 标签 | 命中 | 聊天模式 |
| :--- | :--- | :--- |
| 约定 | `我们约定`、`记得提醒我`、`约好了` | 仍按饥饿 / 困倦 / 陪伴，不新开模式 |
| 传授 | `我教你`、`定义是`、`步骤是` | 陪伴。不是知识问 |
| 知识问 | 原有疑问词，且不像单纯抒发 | `knowledge` |

「我是不是该辞职」保持闲聊或倾诉，不进知识。只含「辞职」但同时有「怎么 / 是什么」时按知识问。玩笑仍在倾诉之后，避免「哈哈我是火星人」被记成传授。

本批不因为约定或传授提前封窗，也不写记忆。测试补算法施工的验收向量：走失问知识在服务层仍是 `SPIRIT_NOT_HOME`，不进入 `recall_only`；「假如我是宇航员，开玩笑」主标签是玩笑。

## 批次 8：抽取结果改走准入 — 已完成

Worker 在模型返回后把每条候选交给 `admit()`。拒绝的丢掉，不补写。通过的按信号优先级最多留 2 条。摘要仍用 500 字上限。

抽取仍在记忆模块。聊天只继续在满 3 个普通轮时发一个任务。Worker 在模型返回后：

1. 丢掉口癖样本和性格 delta，保持现有 `discard_extract_side_channels`。
2. 每条候选转成 `MemoryCandidate`，调用 `admit()`。拒绝的丢掉，不补写。
3. 通过的再按现有信号优先级截到最多 2 条。
4. 只写通过项。失败窗口保持 `failed`，对话消息不动。
5. 已成功窗口重放仍返回第一次结果。

摘要长度本批仍用现有 500 字上限。不把门槛改成 8–40。证据摘句是否必须是用户原句的连续片段，见文末。

测试：玩笑候选 0 条；置信度 0.5 拒绝；精灵口吻当证据拒绝；同一窗口第二次成功不增加记忆行。

## 不进本方案的项

这些和已落地行为或两份施工说明书冲突，选定之前不写代码：

- 提前封口。业务施工只写满 3 个普通轮。Agent 细则还写本窗出现改口、纠正、勿记、记住就封口。未选定。
- 摘要必须 8–40 个汉字，证据摘句必须是用户原句的连续片段。只在 Agent 细则。现行准入没有这条，本方案不改 `SUMMARY_MAX`。
- 口癖样本轨道、14 天 5 次门槛。算法施工写一期不用。
- 天气、节日写进指令包。算法施工禁止天气驱动；节日日历没有确认过的数据来源。
- 知识依据四层重写，以及界面是否露出依据类型。检索保持现状。
- 校验失败对用户显示「它这轮没说清楚」还是降级短句。业务施工写降级短句，批次 2、3 按这个做。
- 把走失 / 出门改回短句，或在走失时单独放行安全固定稿。

做完批次 1 到 8 之后，在家聊天才会先分类、只给白名单、生成后再审；抽取才会按准入闸门落记忆。两套 Agent 的十二步和九步里，没列入上面批次的步骤仍然不做。
